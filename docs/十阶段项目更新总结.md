# 汽车供应链路径推荐项目十阶段更新总结

> 完成日期：2026-07-26  
> 项目：`supply-chain-api`  
> 当前推荐评分版本：`route-recommendation-v1.2`  
> 当前数据库快照：`2026-07-26T11:40:05Z`，数量会随定时任务变化

## 1. 最终结论

本轮十个阶段已经把项目从“返回静态路段和大量默认风险值的图谱 API”，推进为具备以下能力的后端：

1. 使用供应商、起点、终点、汽车货物和偏好生成多条候选路径；
2. 支持最低风险、最低成本、最快、综合和自定义权重；
3. 风险只使用仍在有效期内且可追溯的 GDELT、Open-Meteo、AISStream.io 数据；
4. 缺失风险返回 `null/unavailable`，不再用 `0.5` 或 `50` 冒充中等风险；
5. 成本和时效返回状态、区间、置信度、公式与假设，不把估算称为报价；
6. 路线端点返回名称、经纬度来源和坐标状态，可供前端画图；
7. 根据路线 geometry 与风险区空间相交，支持高风险区域绕行和重新排序；
8. GDELT 与 Open-Meteo 可由 GitHub Actions 每小时直接更新 AuraDB；
9. AISStream.io 已有后端消费者、四个订阅区域、聚合和查询接口；
10. 具备只读审计、dry-run、安全清理、幂等迁移、自动测试和中文部署文档。

项目还没有达到“全球真实物流交易平台”的生产数据覆盖。当前最大的限制不是 FastAPI 接口，而是大部分路线仍是参考或模拟数据，缺少承运商、真实班期、真实报价、铁路网络和持续 AIS worker。前端可以开始对接统一推荐接口，但必须把“真实观测、参考数据、估算和不可用”明确展示给用户。

### 阶段 5：GDELT 去重与路线天气进入评分

GDELT：

- 规范 URL，校验 UTC、未来时间和异常时间；
- 按 48 小时窗口和标题相似度聚类；
- 增加冲突、制裁、贸易政策、关税、罢工、中断、事故、灾害和海关延误分类；
- 同一事件的大量转载只计一次；
- 原始文章继续作为 Evidence 保留；
- 路线新闻风险默认 3 小时 TTL。

Open-Meteo：

- 沿路线几何默认采样 5 点；
- 没有几何时使用低置信度端点回退；
- 超出 168 小时预报窗口的数据不冒充未来天气；
- 按运输方式使用不同天气维度；
- 路线天气默认 2 小时 TTL，并进入主推荐风险。

新增每小时工作流：

```text
.github/workflows/update-gdelt-risk.yml
.github/workflows/update-weather-risk.yml
```

影响：近期新闻和天气可以改变风险与路线排序；过期数据自动退出，不需要前端自行判断算法有效性。

### 阶段 6：坐标、路线 geometry 与空间风险区

完成：

- 102 个 `TransportLocation` 全部具有坐标审计状态；
- 89 个有来源坐标，13 个明确 `unavailable`；
- 10 个 `GeoZone` 具有 GeoJSON；
- 5 条海运和 5 条公路具有估算网络 geometry；
- 5 条铁路只保留端点回退；
- 4 条跨海洋纯公路/铁路标记 `invalid_cross_ocean`；
- 建立 69 条 `PASSES_THROUGH`，其中 65 条有效、4 条软停用；
- 有几何时使用 `geometry_intersection`，否则才使用低置信度 `inferred_from_endpoints`。

主要来源：UN/LOCODE、OurAirports、GeoNames、Natural Earth、Marine Regions、OSRM/OpenStreetMap 和 searoute-py。

影响：前端可以获得名称、坐标状态、GeoJSON 和风险区暴露证据；算法不再只根据起终点国家猜测所有海域。

### 阶段 7：AISStream.io 港口船流与拥堵

新增：

- 后端 WebSocket 消费器；
- 上海、新加坡、鹿特丹和苏伊士四个订阅区域；
- 不依赖预先提供 MMSI 的边界框订阅；
- MMSI、IMO、船名、船型、位置、速度、航向、目的地、吃水和导航状态解析；
- 消息去重、异常跳过、心跳、指数退避和重连；
- 每船只保留最新状态；
- 60 分钟窗口生成 `PortTrafficSnapshot`；
- 只有真实且未过期快照才进入海运 `port_congestion`。

当前状态：代码和 4 个监测目标已完成，但没有常驻真实 worker，`PortTrafficSnapshot=0`。这是正确的 unavailable 状态，不会制造拥堵分。

影响：前端已有统一健康、港区流量和船舶查询接口；部署 worker 后无需修改前端即可显示真实聚合结果。

### 阶段 8：统一成本、时效和推荐算法

新增主接口：

```text
POST /api/routes/recommend
```

能力：

- `min_risk`、`min_cost`、`fastest`、`balanced`、`custom`；
- 风险、成本、时效权重之和必须为 1；
- 先应用风险、成本、P90 时效、运输方式、风险区、完整度和 hops 硬约束；
- 使用版本化固定锚点归一化；
- 缺失数据单独施加不确定性惩罚；
- 成本返回 min/mostLikely/max、公式、组件、输入和状态；
- 时效返回移动、等待、海关、中转、延误、P50/P90 和假设；
- 返回为什么推荐、与下一名差异、避开区域、缺失和估算字段；
- 保存 `RecommendationSnapshot` 并支持 routeId 回读；
- 旧 GET 接口保留并标记 deprecated。

数据库变化：新增 3 个推荐快照和 12 条 `INCLUDED_IN` 关系，没有删除数据。

影响：前端从“下载全部路段后自行拼装”改为“一次提交业务需求，直接获得多条完整路线卡片”。

### 阶段 9：测试与真实 AuraDB 验证

## 6. 对前端的具体影响

### 6.1 调用方式改变

旧方式：

```text
GET /api/supply-chain/routes
-> 一次吐出大量路段
-> 前端自己筛选和拼路线
```

新方式：

```text
供应商 -> 可用起点 -> 终点 -> POST /api/routes/recommend
-> 多条完整候选路线
-> 后端完成约束、评分、排序和解释
```

### 6.2 页面可以直接获得的数据

每张路线卡片可使用：

```text
id, rank, name, tags,
riskScore, riskStatus, riskDataCompleteness,
cost, durationDays, distanceKm,
finalScore, uncertaintyPenalty, scoreBreakdown,
costEstimate, durationEstimate,
whyRecommended, comparisonToNext,
missingData, estimatedFields,
riskFactors, legs
```

地图分段带 `from/to` 名称、城市、国家、经纬度、坐标来源和状态；有可用 geometry 时返回 GeoJSON。

### 6.3 前端必须改变的错误处理

- `riskScore=null`：显示“暂无可信风险数据”，不能显示 0 或 50。
- `status=partial`：显示数据不完整和缺失维度。
- `status=stale/unavailable`：显示已过期或未接入。
- `provider=null`：显示模型估算，不能显示承运商名称。
- `coordinateStatus=estimated`：地图可低精度展示，并标注估算。
- `coordinateStatus=unavailable`：不要把 `0,0` 当作真实坐标。
- `200 + routes=[]`：查看 `rejectedCandidates`，说明候选被硬约束过滤。
- `422`：通常是权重不等于 1、供应商起点不匹配或请求字段错误。

### 6.4 前端部署

Vercel 只需要：

```text
NEXT_PUBLIC_API_BASE_URL=https://supply-chain-api-kyiy.onrender.com
```

Render 的 `API_CORS_ORIGINS` 必须包含实际 Vercel 域名。数据库密码、AIS Key 和管理员 Token 不能进入前端。

## 7. 当前真实数据与估算数据

| 数据 | 当前性质 |
|---|---|
| GDELT 文章元数据 | 外部 API 观测；分类、聚类、严重度和路线分数由项目计算 |
| Open-Meteo 天气 | 数值天气预报；路线采样和风险由项目计算 |
| AISStream.io | 代码已完成，但当前无真实聚合快照 |
| 港口/机场/城市坐标 | UN/LOCODE、OurAirports、GeoNames 等参考数据 |
| 海运/公路 geometry | 开源网络估算，不是承运商实际轨迹 |
| 空运大圆线 | 估算，不是航班计划 |
| 铁路 geometry | 当前不可用或端点回退 |
| 成本 | 多数为内部费率估算，不是实时报价 |
| 时效 | 多数为距离、速度和假设估算，不是承诺 ETA |
| 综合推荐分 | 版本化算法结果，不是外部观测 |

完整来源、许可证和商业使用注意事项见 `docs/data_sources.md`。

## 8. 目前仍存在的问题

### P0：直接影响推荐可信度

1. **594/613 个路段仍属于 synthetic 或 reference**：可用于算法演示，不能称为已验证运输服务。
2. **535/613 个路段仍使用非规范 mode**：`multimodal`、`delivery`、`truck` 等旧值需要拆分或迁移为 road/rail/sea/air。
3. **21 个路段端点关系异常**：缺少或重复 `FROM_NODE/TO_NODE`，会减少可用候选。
4. **运输 Provider 为 0/613**：没有船公司、铁路运营商、航空公司或公路承运商服务标识。
5. **供应商完整发货链为 0/29**：25 个供应商有旧 `SHIPS_FROM`，但尚未建立目标中的 `供应商→工厂/仓库→接驳段` 完整链。
6. **路线 geometry 仅 10/613**：大多数路线不能可靠判断经过哪个海域、国家或通道。
7. **路线两端都有坐标的分段仅 57/613**：旧标签中的地点仍有大量坐标缺口。

### P1：实时数据和商业信息缺口

1. GDELT 审计时有效路线风险为 0，需要监控每小时任务成功率和 TTL。
2. AIS `PortTrafficSnapshot=0`，必须部署常驻 worker。
3. 没有海盗、边境等待、铁路中断、机场容量、班期可靠性等真实 Provider。
4. 没有承运商报价、舱位、船期、航班、班列、港杂费、保险和真实关税数据。
5. 目前新闻只衡量来源多样性，没有独立媒体可信度 Provider。
6. Open-Meteo 是预报，不是港口实测或运营关闭状态。

### P2：工程与产品完善

1. 15 组地点标识重复需要区分多标签别名和真正重复实体。
2. AIS 高频轨迹尚未进入 TimescaleDB/PostgreSQL 等时序存储。
3. 缺少独立 `GET /api/routes/{route_id}/evidence` 聚合端点。
4. 管理接口还需要完善鉴权轮换、速率限制和操作审计。
5. 需要 Provider 新鲜度告警、GitHub Actions 失败告警和数据质量仪表盘。
6. 需要使用真实到货、成本和事故结果校准风险权重、P50/P90 和不确定性惩罚。

## 9. 未来应该怎样解决

### 第一步：先修图，不要先扩大算法

1. 修复 21 个端点异常分段。
2. 对 535 个旧 mode 分批分类：
   - `truck -> road`；
   - `delivery` 根据真实含义拆成 road/sea/rail/air；
   - `multimodal` 拆成多个不同 mode 的 RouteSegment；
   - 无法解释的保持 `unavailable` 或软停用。
3. 建立真实的：

```text
Supplier-[:SHIPS_FROM]->Factory/Warehouse
Factory/Warehouse-[:HAS_ACCESS_LEG]->Port/Airport/RailTerminal/RoadTerminal
```

4. 为每次修复写 dry-run、备份、MERGE 迁移和回归测试。

### 第二步：补真实运输网络

- 公路：自建或签约 OSRM/OpenRouteService 数据服务，并保存数据版本。
- 海运：获取可合法使用的班轮航线、港口挂靠和服务频次；开源 geometry 只作 fallback。
- 铁路：接入铁路基础网络、跨境口岸、轨距换装、运营线路和中断公告。
- 空运：接入货运机场、真实航线/航班和空域状态；大圆线继续标 estimated。
- 每个服务路段保存 Provider、服务 ID、有效期、来源 URL 和审核状态。

### 第三步：补报价、班期和延误

优先通过合法合同或 Provider API 获取：

```text
承运商报价、有效期、币种、货物条件
船期/航班/班列、截关和预计到达
港杂费、装卸费、燃油附加费、保险、关税
历史实际到达和延误
```

没有数据时继续返回 estimated/unavailable，不创建虚假船名、航次、航班或报价。

### 第四步：让实时风险可靠运行

1. 为两个 GitHub Actions 增加失败通知和最近成功时间监控。
2. 部署 AIS 常驻 worker，并检查 `/health/ais`。
3. 为 AIS 增加第二 Provider 或断线降级方案。
4. 把 AIS 原始高频位置写入专用时序库，Neo4j 只保留最新状态和聚合。
5. 接入官方制裁、海事安全、海关、口岸和基础设施公告，并建立 Evidence。

### 第五步：用真实结果校准算法

收集实际路线选择、成本、到货时间、延误、事故和用户偏好，按时间切分训练/验证数据。比较推荐与实际结果，更新固定锚点、风险权重、P90 倍数和惩罚系数，并提升 `scoring_version`。

## 13. 安全提醒

- 不要提交 `.env`。
- 不要把 AuraDB 密码、AIS Key 或管理员 Token 发给前端。
- 不要执行无条件 `MATCH (n) DETACH DELETE n`。
- 不要把 `null` 风险变成 0 或 50。
- 不要把估算成本称为实时报价。
- 不要把开源路线 geometry 用于导航。
- 不要把 AISStream.io Beta 服务当作有 SLA 的唯一生产 Provider。
